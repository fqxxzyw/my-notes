# Python 项目环境搭建与基础服务笔记

> 根据视频文案整理。主题包括 Python 虚拟环境、依赖安装、PyCharm 配置以及 Docker Compose 中间件。文案中部分命令、版本和画面内容缺失，实际操作以项目文件及课程提供的资料为准。

## 一、整体流程

1. 使用指定版本的 Python 创建虚拟环境。
2. 按项目要求安装依赖，并检查依赖冲突。
3. 在 PyCharm 中选择已创建的虚拟环境。
4. 启动项目需要的 Docker 服务。
5. 在 PyCharm 中配置数据库连接，测试能否连接。
6. 通过 Attu 查看 Milvus 中的集合和数据。

## 二、Python 虚拟环境

### 1. 虚拟环境的作用

虚拟环境为项目提供独立的 Python 包安装位置，使不同项目可以使用不同版本的依赖，减少相互影响。它包含自己的解释器入口和环境配置，但底层解释器可能通过复制或链接使用基础 Python，并不一定是完整安装了一份全新的 Python。

### 2. 创建与使用

以 Windows PowerShell 为例：

```powershell
# 在当前目录下创建名为 .venv 的虚拟环境
python -m venv .venv

# 激活环境（可选）
.\.venv\Scripts\Activate.ps1

# 查看当前 Python 版本
python --version
```

激活后，终端提示符通常会显示环境名称，例如 `(.venv)`。也可以不激活，直接调用环境中的解释器：

```powershell
.\.venv\Scripts\python.exe --version
```

> 创建环境时使用的是命令所指向的 Python 版本；课程中提到了 Python 3.11，但实际项目的版本要求以项目说明为准。如果 PowerShell 限制脚本执行，可直接使用虚拟环境的解释器路径，不必激活。

## 三、安装依赖与排查冲突

### 1. 从依赖文件安装

在 `requirements.txt` 所在目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果环境不在当前目录，替换为该虚拟环境中 `python.exe` 的实际路径。如需指定 PyPI 镜像，可使用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

命令含义：

- `python -m pip`：使用指定 Python 解释器运行 `pip` 模块，确保依赖安装到对应环境。
- `install`：安装包。
- `-r requirements.txt`：从指定文件读取依赖列表；文件名可以不同，但命令中的名称要与实际文件一致。
- `-i`：指定包索引地址，即安装时使用的源。

### 2. 关于安装顺序

视频强调先安装一个指定版本的 LangChain 相关包，再安装依赖文件。**本段文案没有给出该包的准确名称、版本或依赖文件内容**，无法还原完整命令，应查阅课程提供的命令或项目说明。

安装顺序可能影响最终环境，但不能保证解决版本冲突；后续安装也可能升级或降级已安装的包。应尽量使用互相兼容的版本，并在安装后验证。

### 3. 检查依赖

```powershell
.\.venv\Scripts\python.exe -m pip check
```

该命令检查已安装包声明的依赖是否满足。例如，一个包要求 `langchain-core` 在某个版本范围内，而实际安装的版本不在范围内，就会报告冲突。根据报告调整依赖版本，再运行检查和项目测试。

`WARNING` 表示警告，`ERROR` 表示错误，但警告不一定都可以忽略：有些警告会提示依赖冲突或后续运行风险，需要结合内容判断。

### 4. 版本选择

- 项目已有依赖配置时，优先使用项目验证过的组合。
- 新项目应综合考虑兼容性、维护状态和安全更新，选择经过验证的版本，而不是单纯追求最新或最旧。
- 可以借助 AI 辅助分析冲突，但仍需检查其建议，并通过安装和实际运行验证。

## 四、PyTorch：CPU 与 GPU 版本

视频提醒，安装 PyTorch 时需要考虑是否使用 GPU。Windows 下可运行：

```powershell
nvidia-smi
```

如果命令可用，可以查看 NVIDIA 显卡、驱动以及显示的 CUDA Version。这里的 CUDA Version 通常表示驱动支持的最高 CUDA 版本，**不等同于本机已安装的 CUDA Toolkit 版本**，也不能单独决定应安装哪个 PyTorch 构建。

应根据显卡、驱动、项目依赖和 [PyTorch 官方安装说明](https://pytorch.org/get-started/locally/)选择合适的安装命令；不需要或不能使用兼容 GPU 时，可选择 CPU 版本。原文无法可靠还原课程要求的 PyTorch 精确版本，不宜自行猜测。

## 五、在 PyCharm 中配置解释器

1. 打开 PyCharm 设置，找到 **Python Interpreter**。
2. 添加本地解释器，选择**已有环境**（Existing），而不是新建环境。
3. 选择虚拟环境中的解释器，例如 Windows 下的 `.venv\Scripts\python.exe`。
4. 确认保存，并检查项目运行配置使用了该解释器。

界面名称会随 PyCharm 版本变化。配置完成后，编辑器和项目运行使用的 Python 环境就能与安装依赖时保持一致。

## 六、配置 MySQL 连接

视频通过 JetBrains 的数据库工具配置连接。具体数据库功能是否可用取决于所用 IDE 的版本与功能配置。

1. 在数据库工具窗口中添加 MySQL 数据源。
2. 填写数据库地址、端口、用户名和密码。
3. 根据提示下载或配置 MySQL JDBC 驱动。
4. 点击 **Test Connection** 测试连接，成功后保存。

课堂示例使用了虚拟机地址 `192.168.88.101` 和 MySQL 端口 `3306`；地址和账号密码均应以自己的环境为准，不是通用配置。

连接失败时，可依次检查虚拟机和数据库服务是否启动、地址和端口是否正确、账号权限、网络和防火墙，以及驱动配置。

## 七、使用 Docker Compose 启停服务

进入包含 `docker-compose.yml` 或其他 Compose 配置文件的项目目录：

```bash
# 后台启动服务
 docker compose up -d

# 查看服务状态
 docker compose ps

# 查看服务日志
 docker compose logs

# 停止并移除 Compose 创建的容器和网络
 docker compose down
```

`-d` 表示以后台模式运行。显示容器已启动不代表应用一定已经准备好；服务可能还需要初始化，可通过状态、日志和实际连接进一步确认。

视频建议停止服务后再关闭虚拟机。执行 `down` 前，先确认当前目录和目标项目；命令默认不会删除命名卷，数据是否保留仍取决于具体存储配置，`-v` 会额外删除卷。

## 八、项目中提到的服务

| 服务 | 作用 | 视频提及的端口 |
| --- | --- | --- |
| MySQL | 关系型数据库，使用表等结构管理数据 | `3306` |
| Redis | 内存数据存储，常用于缓存等场景 | `6379` |
| Milvus | 向量数据库，用于存储与检索向量等数据 | `19530` |
| Attu | Milvus 的 Web 管理界面，可浏览集合和数据 | 课堂示例为 `3000` |
| etcd | 提供键值存储及协调能力，常用于 Milvus 的元数据和服务协调 | 以部署配置为准 |
| MinIO | 对象存储服务，可存储文件等对象数据 | 以部署配置为准 |

端口和服务依赖取决于实际 Compose 配置。Milvus 是向量数据库，不能简单理解为在关系型数据库上加一个向量字段。etcd、MinIO 的具体使用方式也会因 Milvus 版本和部署方式不同而变化。

### 通过 Attu 查看 Milvus

1. 确认 Milvus、Attu 等所需服务已启动并完成初始化。
2. 使用浏览器访问部署环境中的 Attu 地址；视频示例为 `http://192.168.88.101:3000`。
3. 在 Attu 中连接 Milvus；视频提及 Milvus 的默认端口为 `19530`。
4. 进入数据库与集合，查看字段和数据。

Attu 的 Web 访问端口与 Milvus 服务端口不是同一个。课堂演示环境可能简化了认证，实际连接方式以自己的部署配置为准。
