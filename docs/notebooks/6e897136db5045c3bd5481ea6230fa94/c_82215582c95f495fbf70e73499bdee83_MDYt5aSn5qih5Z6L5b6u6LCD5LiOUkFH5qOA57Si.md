# 06 · 大模型微调、蒸馏与本地 RAG (`model-service/` & `translation/`)

如果用户不想花钱买云端 API Key，或者想在断网环境下和雪乃聊天，就会用到 **`model-service/`**（本地对话模型）和 **`translation/`**（本地翻译模型）。

---

## 1. 为什么选 1.5B 小模型 + LoRA 微调？

本项目的本地基座模型锁定为 **`Qwen/Qwen2.5-1.5B-Instruct`**（约 15 亿参数）。因为普通用户的电脑显存只有 4GB~8GB（甚至只有核显/CPU），7B 或更大的模型根本跑不动。

### 1.1 什么是 LoRA / QLoRA 微调？(`yuki_model/training.py`)
- **全量微调太贵**：把 15 亿个参数全部改一遍需要极高的显存，而且容易把模型原本的通用对话能力改坏（灾难性遗忘）。
- **LoRA（低秩适应）**：冻结原模型所有参数，只在关键的矩阵旁边外挂两个极小的低秩矩阵 $A$ 和 $B$（$W_{\text{new}} = W + A \cdot B$）。训练时只更新这几十 MB 的外挂权重（`adapter_model.safetensors`），既省显存，又能随时插拔或合并（`merge`）进原模型。
- **QLoRA**：在训练时把 1.5B 原模型压缩成 **4-bit 量化** 放进显存，让单张消费级显卡也能轻松微调。

### 1.2 Assistant-Only SFT（只学角色怎么答，不学用户怎么问）
在监督微调（SFT）时，一段对话包含 `System（人设）`、`User（用户提问）`、`Assistant（雪乃回答）`。
代码在计算损失函数（Loss）时，把 `System` 和 `User` 部分的 Token 标签全部设为 **`-100`**（PyTorch 会自动忽略 `-100` 的梯度），**只对 `Assistant` 的回答计算 Loss**。这样小模型有限的记忆力全部用来学习雪乃的说话语气和知识边界。

### 1.3 监督知识蒸馏 (`yuki_model/distillation.py`)
小模型自己很难写出高质量的长对话。项目采用**教师-学生监督蒸馏**：
- 先用更聪明的大模型（教师）结合原作小说切片，生成高质量的雪乃口吻问答对；
- 用 `verify_evidence()` 严格核对每条数据引用的原著段落 **SHA-256 哈希**，确保教师模型没有胡编乱造；
- 再用这些经过核验的数据去训练 1.5B 的学生模型。

### 1.4 原子化断点续训校验
训练大模型最怕中途断电。`training.py` 在保存 Checkpoint 时，必须等权重、优化器状态、随机数状态全部写完后，才计算所有文件的 SHA-256 并写入 `checkpoint-complete.json`。下次恢复训练前先校验哈希，绝对不会加载到写了一半的坏档。

## 2. 本地 RAG 检索与"防幻觉"设计 (`yuki_model/retrieval.py`)

**误区澄清**：很多人以为微调就是把 20 本轻小说（217 万字）全塞进模型参数里。实际上 1.5B 模型根本背不下来，硬背只会导致张冠李戴（幻觉）。

本项目的正确做法是 **微调学语气 + RAG 查资料**：
1. **本地知识库 (`knowledge.sqlite`)**：把 20 本小说清洗切分成 3,011 个段落块 + 人物卡，存在本地 SQLite 数据库里。聊天时先检索最相关的片段塞进上下文。
2. **人物卡直出防幻觉 (`prefer_profiles`)**：
   - 当用户问"雪之下雪乃是谁？""她的姐姐是谁？"这类短而明确的基础事实时，即使把资料给 1.5B 模型，它有时也会在转述时把名字改写错。
   - 因此系统用正则和别名表（如 `雪乃 -> 雪之下雪乃`、`侍奉社 -> 侍奉部`）直接命中人物卡，**跳过模型生成，直接返回原文摘录**（标记为 `source_excerpt`），彻底消灭基础事实幻觉。

## 3. GGUF 量化与端侧推理 (`scripts/export_gguf.py` & `desktop_worker.py`)
- 微调并合并后的模型会被转换成 **GGUF (`q4_k_m`)** 格式（把 16 位浮点数压缩成约 4 位整数，体积缩小到 1GB 左右，普通电脑内存就能装下）。
- 通过 `llama.cpp` 引擎运行，支持 N 卡 CUDA、Mac MPS 以及 Intel/AMD 核显的 **Vulkan** 加速；如果显存不够，会自动减少卸载到 GPU 的层数，直到纯 CPU 稳定运行。
- **`translation/`** 目录采用了同样的 `llama.cpp` + GGUF 技术栈，搭载 **HY-MT2** 翻译模型，实现完全离线的双语互译。
