# 使用纸间

[回到我的书柜](/)

纸间将笔记整理为「书柜 → 笔记本 → 章节」，也可以在书柜里放不属于任何笔记本的独立「书页」。它们都以 Markdown 保存；你可以先在本机写作，再连接自己的 GitHub 仓库进行同步。

## 整理和写作

1. 点击顶部「新建笔记」，选择「笔记本」或「书页」并输入名称。选择已有书柜，或在下拉菜单中选择「新建书柜」；不选时使用默认书柜。
2. 点击书柜，再点击书脊打开笔记本，在章节目录中创建章节。书本较多时，可按住书架横向拖动；触屏可左右滑动。
3. 在书柜的「管理笔记本」中勾选多本，可一起移动到其他书柜。首页的「管理书柜」可以删除非默认书柜：柜内笔记会移入默认书柜，正文不会删除。
   在同一位置点击「重命名」可修改书柜名称；桌面版改名后可通过「同步书柜整理」提交到 GitHub。
4. 编辑器工具栏提供标题、粗体、代码块、列表和链接等按钮；选中文字后可点击按钮应用格式。

编辑时可在侧栏切换「章节」与「目录」，点击目录中的标题即可跳转；标题前的箭头可以折叠或展开下级标题。将标题拖到另一个标题上，会把它及其正文、子标题移到目标标题下；也可以用标题旁的「− / +」调整层级。操作后可用 Ctrl+Z（macOS 为 ⌘+Z）撤销。部分无法安全重排的 Markdown 结构会提示先检查正文。

收起侧栏后，鼠标沿左侧线移动可预览标题，点击即可跳转；点击线条上方的按钮可重新展开目录。目录和正文可以分别滚动，顶部编辑工具会保持可用。

编辑器可切换「源代码」与「所见即写」：代码块会显示背景和常用语言的语法高亮，普通表格单元格和内联图片可在界面中编辑。为保护原文，复杂格式的表格单元格和引用式图片的地址请在源代码中修改。包含旧式单独 CR 换行的文档在所见即写中暂以源码显示，原文不会被自动改写。

在编辑器中直接粘贴图片即可插入；支持 PNG、JPEG、GIF、WebP，每张最多 20 MiB。纸间会把图片保存为独立附件，并在正文写入 `![图片](assets/图片文件名.png)` 这样的相对路径；旧笔记中直接嵌入正文的图片仍可显示。同步笔记时，所引用的图片会一起提交到 GitHub；恢复时可下载图片以便离线查看。

点击顶部「导入」，选择 Markdown 文件或文件夹，也可以将它们直接拖入窗口。在笔记本中导入文件会新增章节；在书柜中导入文件会创建独立书页。导入文件夹会为顶层文件夹创建笔记本，并将其中的 Markdown 文件导入为章节。

同时选择 Markdown 与图片所在的完整文件夹时，纸间会导入标准 Markdown 图片引用所指向的相对路径图片，包括 Typora 的 `.assets` 目录，并将正文中的图片地址改为纸间附件的相对路径。支持 PNG、JPEG、GIF 和 WebP，单张不超过 20 MiB，每次合计不超过 100 MiB。绝对路径、选定文件夹外的资源、HTML 图片和其他类型附件不会自动导入；网络图片仍使用原链接。没有找到或无法导入的资源会提示检查。

如果旧版已导入的笔记缺少图片，可以打开对应章节，点击「导入」→「补齐当前笔记图片」，重新选择包含原 Markdown 文件及图片的文件夹。纸间会保留当前正文和未同步修改，将匹配的图片补入本机；之后可以同步到 GitHub。

草稿会自动保存在当前设备和浏览器中。桌面程序与网页版使用各自的本机存储；清理浏览器网站数据或桌面程序的用户数据前，请先同步或备份需要的草稿。

Windows 便携版将本机数据保存在解压目录下的「纸间数据」文件夹；更换电脑或移动程序时，请一并保留该文件夹。

Windows 单文件版图片保存在 `%LOCALAPPDATA%\PaperNotes\附件`，便携版图片保存在解压目录的 `纸间数据\附件`；文件在目录内按仓库隔离。网页版将图片存放在当前浏览器的 IndexedDB 中。请勿单独删除这些附件或清除浏览器网站数据，否则本机未同步的图片将无法恢复。

## 准备自己的 GitHub 仓库

1. 登录 GitHub，点击右上角 **+ → New repository**，为笔记创建一个仓库。仓库可以是公开或私有：**公开仓库中的笔记任何人都能查看**；需要私密笔记时选择私有仓库。
2. 创建时打开 **Add README**，让仓库产生初始提交，并确保存在名为 `main` 的分支。参见 [GitHub 创建仓库指南](https://docs.github.com/en/repositories/creating-and-managing-repositories/quickstart-for-repositories)。
3. 记下仓库地址或 `用户名/仓库名`。无需预先创建笔记文件夹，纸间同步时会在仓库中写入 `docs/notebooks/` 和 `docs/pages/`。

仓库只用于保存你的笔记时，不必启用 GitHub Pages。笔记能否公开展示是另一个设置；连接自己的仓库不会自动为你部署网站。

## 创建访问令牌并连接

1. 打开 [GitHub 精细访问令牌页面](https://github.com/settings/personal-access-tokens/new)，新建 **Fine-grained personal access token**，填写名称、选择适合的有效期，并将 Resource owner 设为仓库所属账号。
2. 在 **Repository access** 下选择 **Only select repositories**，只勾选自己的笔记仓库。
3. 在 **Permissions → Repositories** 中添加 **Contents**，权限设为 **Read and write**。如找不到该项，先选择 Repositories 标签，再点击右侧的加号添加权限。
4. 点击 **Generate token**，立即复制显示的令牌。离开后无法再次查看该令牌的完整值；如果没有保存，重新生成一个即可。详细操作可参考 [GitHub 令牌指南](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
5. 回到纸间，展开「GitHub 同步设置」，填写仓库的 `用户名/仓库名` 或 `https://github.com/用户名/仓库名`，粘贴令牌并点击连接。纸间会检查仓库访问权限和 `main` 分支。

**令牌相当于仓库钥匙，不要发给别人，也不要写进笔记或提交到仓库。** 网页版将令牌保存在该浏览器的本地存储中，未加密，同站点脚本或浏览器扩展可能读取；请只在可信设备上使用。Windows 桌面版使用当前 Windows 账户加密保存。网页与桌面版各自连接，点击「断开连接」可清除各自保存的令牌。

旧版用户如果之前保存过令牌，可先填写原来的仓库，再选择「使用旧版已保存令牌」并确认仓库归属；连接成功后，笔记数据需另行选择「导入旧版本地数据」，不会自动上传。如果目标工作区已有本机数据，请先使用「导出旧版本地数据」备份，再检查和整理要导入的内容，避免覆盖。

## 同步、恢复与删除

- **同步**：展开「批量同步」勾选本机笔记，然后点击「同步所选」；顶部「同步」也可以提交已勾选的项目，或同步当前有修改的章节。桌面版的书柜整理通过「同步书柜整理」提交；网页版若连接后启用自动保存，会自动提交新的更改。
- **恢复**：点击顶部「恢复」，从当前连接的 GitHub 仓库下载书柜、笔记本和章节，保存为本机离线副本。已有未同步草稿会保留。不同设备上的改动需要先同步，再到另一台设备恢复。
- **删除**：在书柜或章节目录的管理入口勾选内容并确认。删除已同步的笔记会在 GitHub 删除成功后清理本机；如果远端版本发生变化，纸间会拒绝删除并提示处理。批量同步区的「删除所选本机项目」对已同步章节只丢弃本机草稿。

如果 GitHub 与本机同时修改同一章节，请先保留草稿，读取远端版本并合并后再同步。切换到其他仓库时，本机草稿按仓库隔离；旧版草稿需要明确确认后才会导入，避免提交到错误仓库。

## 在 GitHub 查看原文

每个笔记本对应 `docs/notebooks/` 下的一个目录，其中 `index.md` 记录笔记本名称，其他 Markdown 文件是章节。独立书页保存在 `docs/pages/` 下。已提交的文件可以在 GitHub 的 **History** 中查看历史版本。

笔记本中粘贴的图片位于对应目录的 `assets/`，独立书页的图片位于 `docs/pages/assets/`。Markdown 文件和图片目录应一起保留，以使相对路径继续有效。为避免误删其他笔记引用的图片，删除笔记时不会自动清理图片文件。
