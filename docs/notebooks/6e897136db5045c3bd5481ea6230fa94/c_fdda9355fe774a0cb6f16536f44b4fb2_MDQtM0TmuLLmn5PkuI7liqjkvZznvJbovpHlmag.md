# 04 · 3D 渲染与动作编辑器 (`src/scenes/` & `motion-studio/`)

## 1. 3D 角色与程序化场景 (`src/`)

### 1.1 VRM 角色标准 (`@pixiv/three-vrm`)
本项目使用二次元 3D 通用的 **VRM**（基于 glTF/GLB 扩展）标准：
- **Humanoid 骨骼**：统一了头、颈、脊柱、左右臂、手腕的骨骼命名，因此同一套动作可以套用到不同服装的模型上。
- **BlendShape（表情混合）**：控制眨眼（`blink`）、张嘴口型（`aa/ih/ou/ee/oh`，配合语音播放实时驱动）、开心/生气等情绪。
- **SpringBone（物理骨骼）**：自动模拟头发、裙摆、丝带在角色转身或移动时的物理惯性晃动。
- **8 权重蒙皮兼容 (`src/ui/eight-weight-skinning.mjs`)**：普通 3D 引擎默认每个顶点最多受 4 根骨骼影响，复杂和服/裙子容易撕裂，这里专门做了 8 权重支持。

### 1.2 为什么场景大多是代码"画"出来的？(`src/scenes/`)
传统 3D 游戏需要加载几十 MB 的美术场景文件，而本项目在 `src/scenes/` 里大量使用 **Three.js 程序化建模 + 自定义着色器（Shader）** 来构建教室、樱花溪流、京都寺庙、书店等场景：
- 体积极小（几十 KB 的 JS 代码就能生成整个教室桌椅、黑板、窗户光影）。
- 支持动态昼夜切换（`day-sky.mjs` / `night-sky.mjs`）、积云（`cumulus-sky.mjs`）和穿过树叶的丁达尔光柱（`sun-shafts.mjs`）。

## 2. 独立动作编辑器 (`motion-studio/`)

`motion-studio/` 是一个可以独立运行的 3D 动作制作软件，用来给角色制作动作并导出为 `.glb` 给主程序使用。

### 2.1 核心算法：解析法 2-Bone IK (`motion-studio/src/ik.ts`)
在 3D 动画里，**FK（正向运动学）** 是你旋转肩膀、再旋转手肘，才能让手到达某个位置，非常麻烦；**IK（逆向运动学）** 则是你直接把"手腕"拖到目标点，程序自动反推出肩膀和手肘该转多少度。

`solveTwoBone(root, mid, end, target)` 用**初等几何（余弦定理）**直接算出解析解，速度极快且不会抖动：
1. **量长度**：算出大臂长度 $a$ 和小臂长度 $b$，并把目标距离 $d$ 限制在 $[|a-b|, a+b]$ 之间（手臂再长也够不到更远的地方，防止数学报错）。
2. **定弯曲平面**：保留手肘原本朝向的弯曲方向（比如手肘是往外拐而不是往里折），避免关节突然翻转。
3. **余弦定理算肘部位置**：
   - $\text{along} = \frac{a^2 - b^2 + d^2}{2d}$（肘部在"肩→目标"连线上的投影距离）
   - $\text{lift} = \sqrt{a^2 - \text{along}^2}$（肘部垂直抬起的高度）
4. **转回局部坐标系**：算出世界空间的旋转四元数后，乘以父骨骼世界旋转的逆矩阵，转换成相对父骨骼的局部旋转角度应用上去。

### 2.2 动作混合与导出 (`motion-studio/src/motion/`)
- `joint-limits.ts`：给每个关节加上人类生理角度限制（比如膝盖不能向前弯曲）。
- `timeline.ts` & `transition.ts`：时间轴关键帧与动作切换时的平滑插值过渡。
- `retarget.ts`：动作重定向（把身高 1.6m 模型的动作适配到 1.5m 的模型上）。
- `export-glb.ts`：把编排好的关键帧烘焙（Bake）成标准 `.glb` 动画文件。
